# Vault Documentation Style

Write simple, formal British English that preserves the document's facts and makes its purpose clear.

For work in Vault, read its `AGENTS.md` and `projects/vault/guides/markdown-style.md`. Resolve these from the supplied repository or document location. The guide owns the detailed preferences; the core rules below also work when that guide is unavailable. Do not claim to have read an unavailable guide.

## Apply the style

- Lead with the purpose, outcome or proposed change. Use concrete nouns, active verbs and consistent terms.
- Use concise paragraphs for connected explanations: the need, approach, implications and relevant next action. Retain technical detail required by a specification, reference or procedure.
- Use bullets for distinct requirements or actions, numbered steps for ordered work, and tables for comparisons. Add headings only when they help navigation.
- Remove filler, repetition, promotional claims, stock AI phrasing and conclusions that merely repeat the document.
- Preserve conditions, uncertainty, source attribution, evidence scope and material limitations. An accepted design is still unimplemented until implementation is evidenced; record verification separately.

## Revise the existing document

Read the surrounding text and update the appropriate maintained document in place. Keep frontmatter, code, quotations, identifiers, links and historical completion checkpoints unchanged unless the request targets them. Correct historical facts with a dated amendment that retains the original account.

Keep images and editable diagram sources at their existing paths. For new assets, follow Vault's guide and use relative links. A prose edit does not require creating a new document, directory, diagram or template.

Before delivery, compare the revised account with the source for lost meaning, changed status or broken references. Run applicable existing document checks when editing repository files, and report only checks actually performed.
